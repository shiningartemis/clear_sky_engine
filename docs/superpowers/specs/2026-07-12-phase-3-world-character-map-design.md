# 阶段 3：世界、角色、动态属性与地图设计

## 1. 目标与阶段边界

阶段 3 采用纵向可运行切片，交付从角色库、世界创建到真实地图与角色立绘展示的完整本地流程。实现顺序为：

1. 全局角色主表、世界变化值与最终属性合成；
2. 世界创建、唯一主角与 NPC 引用；
3. 地图和角色图片资源发现、复制与安全响应；
4. 总地图与 6 张地点地图；
5. 角色库、世界角色只读页和真实浏览器验收。

阶段 3 只创建内部初始分支，不开放分支创建或切换。世界角色变化记录使用 `(world_id, role_id)` 唯一约束。阶段 5 开放分支功能前必须单独设计并迁移分支状态，不能让多个可切换分支共享同一份变化值。

阶段 3 建立动态属性定义、最终值合成、更新意图 Schema 和通用更新函数；故事分析 AI、受控 Skill 调用、轮次原子提交属于阶段 4。场景 CG 与表情差分只保留可扩展资源契约，不在阶段 3 实现 AI 选择。

## 2. 世界创建

- 世界名称不由用户填写，界面统一显示为 `世界 {id}`。
- 新世界固定从星期一、Day 1、morning 开始。
- 创建引导只填写唯一主角的名称和基础人设。
- 在一个短事务中原子创建世界、内部初始分支、全局角色主记录和世界主角变化记录；任一步失败全部回滚。
- 每个世界恰有一个不可移除的主角。NPC 从全局角色库选择，同一角色不能重复加入同一世界。
- 删除世界只删除该世界的引用、变化值和位置规则，不自动删除全局角色。

## 3. 两张角色核心表

### 3.1 角色主表

角色主表是全局角色库和属性字段集合的唯一事实来源，保存：

- 不可变角色 ID；
- 创建后不可变且全局唯一的角色名称；
- 基础人设、系统提示词和世界书等平铺配置；
- 单层基础属性定义。

基础属性必须使用稳定 key，最终角色配置和发给 AI 的属性均为单层 key-value，不允许对象嵌套。属性定义可以增删，基础值、约束、含义和更新规则可以编辑。

基础值 key 集合是属性字段事实来源。类型、显示名、含义、更新规则和允许操作必须覆盖完全相同的 key；可选约束和示例只能引用这些 key。整组定义在一个事务中校验和保存，不能留下半套元数据。

### 3.2 世界角色变化表

世界角色变化表同时表示世界引用和世界状态，保存：

- `world_id`；
- `role_id`；
- `kind`：player 或 npc；
- 启用状态；
- 单层世界变化 JSON；
- 状态版本和最近更新时间。

数据库以 `(world_id, role_id)` 保证每个世界中的每个角色恰有一条变化记录，并以部分唯一约束保证每个世界只有一个 player。主角记录不可删除。

被任何世界引用的角色禁止从角色库删除，界面列出引用世界。用户必须先从所有世界移除对应 NPC 或删除引用世界，才能删除角色主记录。

## 4. 动态属性定义与最终值合成

每个属性至少包含：

- 稳定 key，创建后不可修改；
- 显示名称；
- 数据类型：integer、number、string、boolean 或 enum；
- 基础值；
- 含义说明；
- 更新规则；
- 允许操作；
- 可选数值上下限或枚举选项；
- 可选的“应更新”和“不应更新”短例子。

数值允许 increment、decrement、replace；字符串、布尔和枚举只允许 replace。

最终值合成始终以角色主表为主：

1. 只遍历主表当前存在的属性 key；
2. 世界变化缺少该 key 时直接使用基础值；
3. 数值把世界值作为变化量，最终值为基础值加变化量；
4. 非数值存在世界值时替换基础值；
5. 只存在于世界变化中的遗留 key 静默忽略；
6. 类型不兼容的世界值忽略并回退基础值；
7. 基础属性删除后保留但忽略遗留世界值；以后恢复同名同类型 key 时旧世界值重新参与计算，同名不同类型时继续忽略；
8. 约束在写入更新意图时校验，读取已有异常数据时不阻断世界打开。

世界角色页只展示最终值与最近更新时间，不展示或编辑基础值、变化值或计算过程。基础属性、约束和规则只能在角色库编辑；世界变化值只能由成功轮次的受控程序更新。

## 5. AI 属性更新链路

动态属性不生成专用脚本，也不解析自由文本。所有属性使用同一套元数据驱动的受控 Skill 和通用更新函数：

1. 故事任务生成角色故事和结构化客观事件；
2. 属性分析任务按角色并行，只接收该角色本轮相关事件、当前最终属性和属性规则；
3. AI 可通过只读 Skill 渐进读取属性定义；
4. AI 通过统一 Skill 提交结构化更新意图：角色 ID、属性 key、operation、value 或 amount、触发依据和来源事件；
5. Skill 只收集意图，不持有数据库事务，也不直接写数据库；
6. 程序校验角色、属性、操作、类型、约束、状态版本和本轮事件来源；
7. 任一意图无效时不做部分更新，由任务修正或使本轮失败；
8. 最终短事务调用唯一通用更新函数，把合法意图合并进世界变化 JSON，并与故事、事件和时间推进原子提交；
9. 下一轮重新计算最终属性，AI 只接收最终值。

数值 replace 根据目标最终值和当前基础值反算世界变化量；非数值 replace 保存世界覆盖值。Skill 不得执行任意 SQL、Shell、文件写入或动态代码。

## 6. 页面与交互

应用首页是世界列表。世界卡片显示系统名称、Day、星期、主角、NPC 数量和最后游玩时间，不提供世界重命名。

全局导航包含：

- 世界；
- 角色库；
- AI 设置。

角色库使用“列表 + 编辑面板”，负责创建角色、编辑基础人设与属性定义、查看引用世界和删除保护。保存角色前必须能在角色资源目录解析出同名默认立绘。

世界角色页固定置顶主角，并显示 NPC 列表、启用状态、位置规则和只读最终属性。NPC 从角色库搜索加入；已加入角色不得重复选择。所有页面提供 loading、empty、error、disabled、删除确认和 retry 状态。

视觉风格沿用阶段 2 的深色半透明面板、蓝色高亮、CSS Modules 和清晰键盘焦点，不引入大型 UI 库。

## 7. 地图背景

仓库 `resource` 中的 7 张地图是内置默认地图来源。实施时复制到项目资源目录，启动时只把缺失文件复制到 `%LOCALAPPDATA%\ClearSkyEngine\content\maps\`；已有文件永不覆盖。

`map_manifest.json` 保存稳定 ASCII scene ID、中文文件主体、地点顺序、场景类型和归一化锚点，不保存扩展名。地图按 `.jpg`、`.png` 顺序解析；两者同时存在时固定使用 `.jpg`。地图只要求横向 16:9，像素尺寸可变。

Phaser 使用 1920×1080 逻辑坐标和统一 cover 变换。背景、锚点、角色位置和碰撞配置共享同一缩放与裁切变换，配置不得依赖某张图片的绝对像素。非 16:9 视口居中裁切，关键交互位于安全区域。

文件缺失、无法解码或比例明显错误时记录可理解诊断并回退内置默认图。地图响应使用 `Cache-Control: no-cache`，替换素材后刷新浏览器即可重新验证。

总地图支持 Left/Right、鼠标选择、再次点击或 Enter 进入。地点地图支持返回总地图和基础边界移动。上述操作均不推进时间。

## 8. 角色图片与未来场景 CG

可编辑目录使用以下结构：

```text
content/characters/{角色名称}/
  {角色名称}.{ext}
  {描述}.{ext}
```

角色文件夹必须等于全局唯一角色名称。默认立绘文件主体必须等于角色名称；其他同目录图片使用描述作为主体，作为未来表情差分或场景 CG 候选。

同名资源按 `.jpg`、`.jpeg`、`.png`、`.gif`、`.webp`、`.avif`、`.bmp` 的稳定顺序取第一张。SVG 因可能包含脚本或外部资源而不支持。GIF 使用浏览器原生动画。资源扫描器统一返回角色、文件主体、URL 和展示模式，未来选择规则不把具体表情或 CG 名称写死。

阶段 3 只实现默认立绘。每个立绘位于带窄边框和轻微暗色底的 1:1 相框中，使用 contain 完整展示，不裁切、不拉伸，短边留空。相框位于地图安全区域下方，单行从左到右排列，主角第一，其余 NPC 按稳定角色 ID 排序；尺寸随角色数和视口在约 128–220 逻辑像素之间调整。窗口过窄时提示放大，不无限缩小。

每个地点最多容纳并显示 6 个角色。主角优先，其余 NPC 按稳定角色 ID 取前 5 个；溢出 NPC 本时间段标记为不在可进入场景中，继续参与离屏推演，但不能与该地点角色直接互动。

未来场景 CG 使用全屏 contain 模式，深色幕布承接未填满区域，隐藏地图背景、角色立绘和其他图片层。阶段 3 只保留通用资源描述和展示模式，不实现 AI 选择。

## 9. 模块边界

- `character/`：全局角色主表、名称唯一、世界引用和删除保护；
- `attribute/`：属性定义、最终值合成、更新意图 Schema 和通用更新函数；
- `world/`：世界创建事务、唯一主角、NPC 引入和系统显示名称；
- `game/`：地点目录、位置规则、6 人容量和离屏状态；
- `resources/`：地图与角色资源发现、复制、格式优先级、校验和安全响应；
- `workflow/`：阶段 4 接入属性分析、受控 Skill 与最终原子提交；
- `api/`：DTO 解析、Service 调用和 HTTP 错误转换。

## 10. 失败与一致性

- 世界创建全有或全无；
- 重复角色名称、重复世界引用和删除被引用角色返回明确冲突；
- 默认立绘缺失或损坏时角色库显示错误，角色不能新加入世界，已有世界不伪造替代立绘；
- 地图异常回退内置默认图；
- 图片发现和解码期间不持有数据库事务；
- AI 更新意图无效时不产生部分属性更新或时间推进；
- 图片不进入 SQLite；
- 最终属性、角色可见性和地点容量由后端裁决，前端不推断。

## 11. 测试与验收

阶段 3 必须覆盖：

- 最终值合成的表驱动测试；
- 角色名称、唯一主角、`(world_id, role_id)` 和删除保护约束；
- 地图与角色资源格式优先级、变分辨率适配、损坏文件、首次复制不覆盖；
- 世界创建回滚、NPC 引入和位置容量；
- 世界引导、角色库、世界角色只读页的组件测试；
- 地图状态机、返回地图和 1–6 人立绘布局；
- 真实 Playwright：把 `天.jpg`、`莫莉莉.png`、`安可儿.png` 复制到隔离测试内容目录，通过网页创建角色、配置属性和位置规则、创建世界、选择主角、加入 NPC，并验证三张真实立绘。三张图片只作测试素材，不创建产品种子数据。

完整轮次接通后增加付费真实 AI Playwright 验收：通过网页配置 Provider 和模型，提交会触发属性变化的主角意图，验证故事、客观事件、结构化更新意图、世界变化值和下一轮最终属性一致。该测试不进入默认检查；无凭据时必须报告“真实 AI 集成未验证”，且不得记录 API Key、完整 Prompt 或敏感响应。
